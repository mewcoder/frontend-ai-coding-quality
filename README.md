# AI Coding 之前，前端工程已有的质量保障手段

本文只讨论前端工程化中的自动化质量保障手段，不包含需求评审、Code Review、手工测试和人工验收等人为介入环节。

在 AI Coding 普及之前，前端工程已经形成了一套完整的自动化质量防线：

```text
代码约束
  ↓
自动化验证
  ↓
交付保障
  ↓
线上监测
```

## 一、代码约束

代码约束的目标，是在代码运行之前，通过规则和工具减少错误产生。

典型手段包括：

- TypeScript 类型检查
- 编译检查
- ESLint、Stylelint
- 代码格式检查
- API Schema 校验
- 依赖版本锁定
- 浏览器目标和语法兼容性检查
- 静态代码安全检查

这一层主要解决：

> 代码是否符合规则，是否能够被正确编译和构建？

## 二、自动化验证

自动化验证的目标，是确认代码运行后的行为是否符合预期。

典型手段包括：

- 单元测试
- 组件测试
- 集成测试
- API 契约测试
- E2E 测试
- 快照测试和视觉回归测试
- 多浏览器自动化测试
- 自动化性能测试
- 自动化可访问性测试
- 依赖漏洞和安全扫描

这一层主要解决：

> 代码运行后，功能、兼容性、性能和安全表现是否合格？

## 三、交付保障

交付保障的目标，是阻止不合格代码进入发布流程，并控制发布过程中的未知风险。

典型手段包括：

- CI 质量门禁
- 测试覆盖率门槛
- 构建产物校验
- Bundle 体积预算
- 构建可复现性检查
- 自动化 Smoke Test
- 灰度发布
- Feature Flag
- 分批放量
- 自动停止发布
- 自动回滚

这一层主要解决：

> 不合格的代码能否被拦截？已经通过检查的代码，如何降低上线风险？

## 四、线上监测

线上监测的目标，是在真实用户环境中自动发现测试阶段未覆盖的问题。

典型手段包括：

- JavaScript 异常监测
- 白屏监测
- API 请求失败监测
- 静态资源加载失败监测
- 页面性能监测
- Core Web Vitals 监测
- 真实用户行为和环境数据采集
- 错误率和关键流程失败率监测
- 自动告警
- 异常趋势识别

这一层主要解决：

> 代码上线后，真实用户是否遇到了异常？问题是否正在扩大？

## 总结

前端工程化质量保障可以归纳为四类：

| 分类 | 核心作用 |
| --- | --- |
| 代码约束 | 减少错误产生 |
| 自动化验证 | 在发布前发现错误 |
| 交付保障 | 拦截不合格变更并控制发布风险 |
| 线上监测 | 发现真实环境中的问题 |

因此，AI Coding 之前的前端质量体系并不是依赖某一个测试工具，而是一条完整的自动化链路：

> 约束错误产生，验证代码行为，控制交付风险，监测线上结果。

## AI Coding 之后

AI Coding 带来的变化，不只是代码生成方式变化，也改变了前端质量保障的重点。

### 1. 代码生成效率提升

AI 可以快速生成代码，减少重复劳动，提升功能开发和交付的速度。

### 2. 测试编写成本下降

过去前端项目中，单元测试和 E2E 测试经常因为编写、维护和补充数据的成本较高而被弱化。

AI 可以辅助生成测试、Mock 数据、测试场景、验证环境和测试脚本。因此，过去“没有时间写、成本太高”的测试，在 AI 时代变得更容易覆盖。

### 3. 代码质量风险同步增加

AI 生成的代码并不天然正确，仍然可能存在业务理解偏差、逻辑错误、隐藏回归，以及性能、安全和可维护性问题。

同时，代码生成得越快、越多，潜在问题出现和扩散的速度也可能越快。

### 4. 质量保障更加重要

AI Coding 一方面降低了测试和验证的成本，另一方面增加了需要被验证的代码数量。

因此，质量保障不再只是上线前的额外投入，而需要成为 AI Coding 流程中的基础闭环：

> AI 提高了代码生产效率，也降低了测试编写成本，但最终能否稳定交付，仍然取决于质量保障体系是否跟得上。

## AI Coding 的质量约束与开发工作流

AI Coding 需要通过一系列约束和工作流，减少生成代码的不确定性，让 AI 在明确的任务、规则和规格下完成开发。

### 1. Prompt

通过 Prompt 对当前任务提出明确要求，包括任务目标、修改范围、实现方式和交付结果。

### 2. Rules / `AGENTS.md`

通过项目规则文件沉淀长期有效的开发约定，例如技术栈、目录结构、编码规范、组件使用方式和架构边界。

### 3. Skills / Commands

将常见开发任务固化成可复用的流程，让 AI 按照统一方式执行特定类型的工作。

### 4. Hooks

在 AI 执行前后自动触发与代码质量相关的检查，例如格式检查、类型检查、测试触发和结果校验。

### 5. SDD

通过规格说明、业务规则和验收标准组织开发过程，明确功能要做什么、边界是什么，以及什么结果才算完成。

这几种手段分别作用于任务指令、项目规则、开发流程、执行检查和需求规格，共同降低 AI Coding 的不确定性。
